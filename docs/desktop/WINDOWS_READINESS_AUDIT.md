# Windows readiness audit — 2026-11-03

Status: implementation in progress; no new production release is approved. Existing published 0.2.1 evidence does not qualify changed source. Audit completed before remediation.

| Reported issue | Severity | Evidence / root cause | Remediation and acceptance |
| --- | --- | --- | --- |
| Undescribed `\\\\` | Unknown | No description or reproducer. Repository test/evidence records are available, but cannot identify a specific bug from this marker. | Keep unresolved; obtain steps, screenshot/prompt text, version and redacted logs. Do not infer an issue from backslashes. |
| Inconsistent original logo | High | `builder.private.cjs` and `builder.dev.cjs` set `signAndEditExecutable:false`; the installed builder explicitly skips icon/resource editing with this option. Only a PNG is committed. NSIS falls back to the executable icon for Installed Apps. | Preserve resource editing while disabling certificate signing in development; generate a multi-resolution ICO from the existing canonical Meldling artwork, configure all Windows resources, inspect actual PE/shortcuts and upgrade on Windows. |
| External browser login | Critical | Existing PKCE + single-use receipt protocol is present. Desktop uses the backend's legacy `android` enum intentionally (the backend only accepts web/android), which already returns `meldiq://auth/callback`. This label alone is not proof of the failure. Direct HTTP redirects to custom protocols can lack an explicit browser handoff; runtime registration is unchecked; pending flows exist only in memory. | Test actual protocol dispatch and cancellation; add verified registration status and actionable recovery; prepare explicit trusted HTTPS browser handoff without weakening state/PKCE. Real provider acceptance remains necessary. |
| PayPal checkout | Critical | Client uses official v6 SDK, account-owned saved purchase IDs and server confirm/status endpoints. Electron popup policy only permits PayPal top-level destinations, blocking Meldiq's own provider return URL; popup close does not notify checkout. Provider webhook/capture behavior is outside this client. | Permit only exact application checkout return paths, close the isolated popup and refresh/verify account-owned purchase server-side; test interruption and idempotent retries, signature/replay/refund/renewal with isolated backend/provider. |
| Subscription purchasing | Critical | Shared catalog and `onSale` flags intentionally gate offers. Client already displays Free/Plus and reads server prices; no safe basis to force production flags on. Existing checkout also offers multiple billing terms. | Retain central source of truth and gate sales. Audit published monthly quote vs required $4.99 centrally; never patch client price to conceal a mismatch. End-to-end sandbox qualification required. |
| Discord import | High | Browser navigation leaves Electron; registered redirect is `/discord/callback`, which is neither a local desktop route nor a native callback. Web sessionStorage/BroadcastChannel cannot deliver across the system browser and Electron. Import/preview/progress/retry backend operations already exist. | Add state-bound native authorization result, HTTPS handoff page, backend-owned verification and real preview/import path. Keep bot-authorized structure only; never claim messages/members are imported. Deployment of browser handoff is a gate. |
| Repeated special permissions | High | App/installer already use asInvoker/per-user/no elevation. App-level media grants are a process-local Set and approved requests use “Allow this session”; denial is not persisted. Actual UAC vs device prompt not yet reproduced. | Persist explicit microphone/camera/speaker decisions, allow reset, deduplicate concurrent dialogs and preserve Windows security controls. Test as standard Windows user; do not classify an unidentified prompt as UAC. |
| Native Windows quality | Medium/High | Native window frame, tray, startup preference, save dialogs, notifications, picker, secure storage, busy updater guards already present. Bounds clamp to the primary monitor even on another monitor; maximized state is not restored. No new hardware measurements yet. | Correct monitor-aware restoration and window-state persistence; verify native integration/accessibility/focus/DPI and actual performance on Windows 10/11. |
| Localization | High | Only en/zh-CN/bn exist; tuple-based catalogs, no RTL, no searchable selector or completeness build gate; many modules and native menus have literal English. | Extend registry/resources and fallback, add RTL and searchable selector, report missing keys and hardcoded UI in CI. Do not label fallback English as a finished translation. Full translation/native-speaker/layout review required. |
| Cross-platform parity | High | Desktop embeds a source snapshot of the shared web client and uses the central API. Backend source examples exist in sibling checkouts; drift from the live owning deployment must be verified. | Document every snapshot adaptation, preserve shared business rules, run isolated backend interoperability and client regression. No production database changes. |
| Production installer/signing | Critical release gate | Certificate-backed release preflight exists. Existing private-update distribution authenticates release metadata with Ed25519, but is not Windows publisher signing. This macOS host cannot certify Windows installer/device/OS behavior. | Keep Authenticode and source-specific functional acceptance required. Do not publish unsigned/unverified artifacts or promote a feed. |

Provider sources reviewed: [Electron protocol handling](https://www.electronjs.org/docs/latest/tutorial/launch-app-from-url-in-another-app), [PayPal webhook verification](https://developer.paypal.com/api/rest/webhooks/), [Discord OAuth2](https://discord.com/developers/docs/topics/oauth2). Discord permits bot access only under granted scopes/permissions; exclusion of messages/members is this import's supported scope, not a blanket claim that Discord has no such APIs.
