# Security review

Status: development review; stable release not approved.

Implemented: sandboxed renderer, contextIsolation enabled, Node integration/webviews disabled, no exposed generic IPC/fs/exec, main-frame sender identity and local-document validation on every handler, separate capture-picker role, bounded preference/token/notification/social payloads, restrictive CSP, no unsafe-eval, HTTPS external links with native confirmation for third-party destinations, navigation/popup restrictions and API document rejection. Packaged files use a manifest and path containment checks; there is no hosted UI fallback. Provider sign-in runs in the system browser and only pending proof-bound receipt IDs can return. No tokens appear in deep links. Unknown/replayed returns are ignored.

Session tokens are encrypted with Electron safeStorage and stored only as OS-sealed bytes in the existing account database; erasing that database erases them. Missing secure storage rejects persistence. Linux basic_text fallback is rejected. This protects persisted token bytes, not an already compromised renderer or OS account. Existing E2EE device keys/history retain the audited web storage architecture; OS hardening of all device/history keys needs separate review before asserting equivalent Android Keystore protection.

Release packaging flips RunAsNode, Node options and CLI inspection off, enables embedded ASAR integrity and restricts loading to ASAR. Production forceCodeSigning and update publisher verification are enabled. Downloads also undergo explicit fail-closed Authenticode/publisher verification before being offered and again before installation. These code paths require real Windows signed-update acceptance. Tests reject malformed output, missing signatures, catalog signatures and mismatched publishers. Unsigned previews disable updates and generate no stable metadata.

The app keeps web account notification/permission/entitlement rules and adds native preferences. Capture always requires source selection. Track cleanup and SDK device-ended fallback are present; physical unplug/reconnect is pending. Cache clearing never calls clearStorageData and was tested to preserve local account storage. Native downloads use a user-controlled Save dialog.

Dependencies: exact versions locked. npm audit initially reported 29 findings (4 high via unused Firebase Firestore/gRPC dependency paths and 25 moderate build-tool/transitive minimatch paths). Remediation/status is recorded in TEST_REPORT.md after dependency checks. Do not describe the entire tree as vulnerability-free. A dependency finding is not waived solely because source builds. Builder/updater compatibility and maintained Electron support must be rechecked for each release.

Unverified/release blockers: production authenticated API/provider access (403 from this machine); production LiveKit/S3/CDN connection origin allowlist (config/desktop.json connectOrigins intentionally starts empty until verified); embedded PayPal/provider navigation acceptance; actual Windows Authenticode and installer behavior; privacy/DND/cross-client dedup; complete feature matrix; hardware benchmark matrix; external signing and release infrastructure. No account, DNS, database, billing or cloud policy was changed.
